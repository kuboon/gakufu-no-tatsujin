# 楽譜の達人

音の高さを色で読む、スマホ横持ちのリズムゲームです。
曲を選ぶとプレイ画面に移り、画面の上半分を五線譜が右から左へ流れます。
音符が判定線に届いた瞬間に、下半分の鍵盤で同じ色の鍵を押してください。

`main` の内容は <https://kuboon.github.io/gakufu-no-tatsujin/> に公開されます。
プルリクエストごとのプレビューURLは、ワークフローがPRにコメントします。

## 遊びかた

判定はバッチリ、ナイス、ミスの3段階です。
続けて当てるとコンボが伸び、最後に点数とランク（S から C）が出ます。
弾く前に曲を聴きたいときは、「おてほん」を押すと自動演奏に切り替わります。

鍵盤は指でタップします。
複数の指で同時に押せます。
パソコンでは、白鍵がホームポジションの A から順に、黒鍵がその一段上のキーに並びます。

鍵盤は白鍵9つで、どの曲でも同じ幅です。
曲ごとに鍵の大きさが変わると、覚えた指の位置がそのたびに崩れます。
曲によって動くのは、その9つがどの音を出すかだけです。

横向きの画面を前提にしています。
縦向きのときは「画面を よこ向きに してね」の案内が全面に出て、演奏中であれば時計も止まります。
案内はCSSのメディアクエリで出しているので、JavaScriptが動き出す前から効きます。

## 音と色

1オクターブの十二音に、色相環を十二等分した色を割り当てています。
ドが0度の赤で、半音上がるごとに30度ずつ回ります。

| 音 | ド | ド♯ | レ | レ♯ | ミ | ファ | ファ♯ | ソ | ソ♯ | ラ | ラ♯ | シ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 色相 | 0° | 30° | 60° | 90° | 120° | 150° | 180° | 210° | 240° | 270° | 300° | 330° |

同じ音は、五線譜の音符でも鍵盤でも同じ色になります。
オクターブが変わっても色は変わりません。
音名が読めなくても、色をたよりに押す鍵を決められます。

リズムは二重に描いています。
ひとつは音符が判定線に届くタイミングそのもの、もうひとつは音符の形です。
全音符は白い丸、二分音符は白い丸に棒、四分音符は黒い丸に棒、八分音符は黒い丸に棒と旗で書き、付点も表せます。
形が読めれば、次の小節を弾く前に長さが分かります。
小節の区切りには縦線を引き、小節番号も添えています。

収録しているのは旋律データだけで、歌詞は含みません。
出典はゲーム内の曲カードにも表示しています。

旋律はどれも保護期間が満了しています。
作曲者不詳の民謡か、没後70年を過ぎた作曲家の曲だけです。
ピアポントは1893年、フォスターは1864年、ヒルは1916年に没しています。
歌詞は詞として別の権利がかかるので、はじめから持っていません。

「さくら さくら」は「やよいの空は」で歌う古い歌詞の版を、14小節すべて収録しています。
「ハッピーバースデー」と「オー・スザンナ」は弱起で始まるので、1小節めが短い小節になります。
「ロンドン橋」は2拍子、「ハッピーバースデー」は3拍子で、ほかは4拍子です。

## 実績

[game-center](https://ga-cen.kbn.one/) に実績を記録します。
ゲームのページには `gamecenter.json` を `<script type="application/gamecenter+json">` として埋め込んであり、ハブはそれを読みに来ます。
実績の定義は `pages/islands/achievements.ts` の一覧が正本で、マニフェストも達成判定も同じ一覧から作ります。

| 実績 | 条件 |
| --- | --- |
| はじめの いっぽ | 「さいた さいた」を最後まで弾く |
| 花の もとにて | 「さくら さくら」を最後まで弾く |
| 5曲 まわった | 5曲を最後まで弾く |
| 10曲 まわった | 10曲を最後まで弾く |
| 全曲 制覇 | 収録曲すべてを最後まで弾く |
| 20コンボ | 20回つづけて当てる |
| ひとつも 落とさない | 1曲をミスなしで弾ききる |
| 全部 バッチリ | 1曲を全部バッチリで弾ききる |
| 楽譜の達人 | ランク S を取る |
| 自己最高 | 自分のいちばん高い得点を記録する |

このほかに隠し実績がひとつあります。

曲ごとの実績があるのは最初の2曲だけです。
そのあと増えた曲は、上の「5曲」「10曲」「全曲」に数えます。
「5曲」と「10曲」は、いま収録している曲だけを数えます。

おてほん（自動演奏）を使った回は、弾いた証にはなりません。
一度でも入れた回では、上の実績はどれも成立しません。

記録の経路は3つで、SDK が通ったものを使います。
ハブの `/play/...` に埋め込まれていれば postMessage、ハブ経由で起動していれば起動トークンで REST、どちらでもなければ claim URL です。
最後の場合は結果画面に「記録する」のリンクが出るので、プレイヤーが自分で押します。
こちらから `window.open` は呼びません。

`.github/workflows/game-center.yml` が、`main` の Pages デプロイが成功したあとにハブへ登録を投げます。
秘密は要りません。
初回だけ作者が <https://ga-cen.kbn.one/dev> で承認すると、以後は同じ URL からの更新が素通しになります。

## 曲を足す

曲は `pages/islands/songs.ts` の1エントリです。
旋律は MML で書きます。
音の時刻、テンポ、小節数、鍵盤がどの音域を出すかは、いずれもそこから導出します。

```ts
song({
  id: "chocho",
  title: "ちょうちょう",
  credit: "ドイツ民謡／野村秋足ほか 作詞",
  lead: "ソから下りてくる。ならんだ音をそのまま読む練習に。",
  difficulty: 1,
  beatsPerBar: 4,
  mml: `
    t108 l4 o4 | g e e2 | f d d2 | c d e f | g g g2
    | g e e2 | f d d2 | c e g g | e1
  `,
});
```

MML の読みかたは `pages/islands/mml.ts` にあります。
使えるのは次のとおりです。

| 書きかた | 意味 |
| --- | --- |
| `c` 〜 `b` | 音符。`r` は休符 |
| `+` `#` `-` | 直前の音名を半音上げる・下げる |
| 数字 | 音長。`c8` が八分音符。省略すると `l` の既定値 |
| `.` | 付点。`c4..` の複付点まで |
| `n` | 音高を MIDI ノート番号で直接指定（`n60` が中央ハ） |
| `t` | テンポ。四分音符あたりの BPM。既定値 120 |
| `l` | 音長の既定値。既定値 4 |
| `o` `>` `<` | オクターブ。`o4c` が中央ハ。`>` `<` は以降ずっと効く |
| `[` `]n` | 繰り返し。回数を省略すると2回 |
| `&` | タイ。同じ高さの音をつなげて1つにする |
| `\|` | 小節線 |

`v`（音量）、`q`（ゲートタイム）、`@`（波形）も読み飛ばせますが、
ゲームは自前の音源で鳴らすので効果はありません。
複数パート（`,`）は、単旋律のゲームなので受け付けません。

MML は拍子を持たないので、1小節の拍数は `beatsPerBar` に書きます。
最初の小節線までが1小節より短ければ弱起とみなし、その分だけ旋律を後ろへずらします。
残りの小節線が小節の頭に来ていなければ、読み込みの時点で例外になります。
旋律全体の長さが小節の整数倍でないときも同じです。
ビルドが失敗するので、書き間違いが静かに紛れ込むことはありません。

鍵盤の白鍵の数は `pages/islands/keyboard.ts` の `WHITE_KEYS` に定数で持っています。
いま収録している中でいちばん広い曲（さくら さくら、シ3からド5）に合わせた9です。
これより広い音域の曲を足すと、読み込みの時点で例外になってビルドが落ちます。
鍵を全曲ぶん小さくしてよいと判断したときだけ、定数を上げてください。

音部記号は省略すると ト音記号です。
低い曲はエントリに `clef: "bass"` を足すと、五線譜がヘ音記号で描かれます。
記号の字形は [Bravura](https://github.com/steinbergmedia/bravura)（SIL OFL 1.1）から取った輪郭で、
`pages/islands/clefs.ts` に置いています。

## しくみ

ゲームは `pages/islands/game.tsx` にあるひとつのアイランドです。
再描画は曲選択、演奏、結果の3画面が切り替わるときだけで、演奏中は一度も起きません。
流れる五線譜はキャンバスに描き、鍵盤の光りかたは既存の要素のクラスを付け外して変えています。

時計には `AudioContext` のものを使っています。
見えている音符と聞こえている音が同じ出来事になり、二つの時計が別々に進んでずれることがありません。
コンテキストを開けない環境や中断された場合は、差分を持ち越した壁時計に切り替えるので、継ぎ目で曲が飛びません。

残りのモジュールはアイランドではない普通のモジュールなので、ブラウザーなしで `deno task test` から呼べます。

| ファイル | 役割 |
| --- | --- |
| `islands/music.ts` | 音高から色相と五線上の位置、音価から音符の形 |
| `islands/mml.ts` | MML の読み取り |
| `islands/songs.ts` | 収録曲 |
| `islands/staff.ts` | 流れる五線譜の描画 |
| `islands/clefs.ts` | ト音記号とヘ音記号の輪郭、五線上の基準位置 |
| `islands/keyboard.ts` | 鍵の範囲と配置、パソコンのキーとの対応 |
| `islands/session.ts` | 時計、判定、フレームループ |
| `islands/audio.ts` | 簡易ピアノの音と、ゲームの時計 |
| `islands/achievements.ts` | 実績の一覧、達成判定、この端末の記録 |

サイトの土台は [Remix v3](https://remix.run) と
[`@kuboon/remix-ssg`](https://jsr.io/@kuboon/remix-ssg) による静的サイト生成です。
`pages/router.ts` が3つのディレクトリをひとつのハンドラーに束ね、`deno serve router.ts` がそれを開発サーバーとして動かします。
ビルドは同じハンドラーを JSR から直接クロールするので、ビルドスクリプトはこのリポジトリにありません。
詳しくは [`pages/README.md`](./pages/README.md) を参照してください。

## 開発

[Deno](https://deno.com) 2.x が必要です。

```sh
cd pages
deno task dev     # http://localhost:8000
deno task build   # 静的サイトを pages/dist に生成
deno task test    # ゲームの土台になっているモジュール
deno task check   # 型検査、lint、フォーマット
```

サブパスに置いたときの動きを手元で見るには、`BASE_URL` を渡します。

```sh
BASE_URL=http://localhost:8000/gakufu-no-tatsujin deno task dev
```

## デプロイ

`.github/workflows/pages.yml` が、再利用可能ワークフロー
`kuboon/workflows/.github/workflows/github-page-with-preview.yaml` を呼びます。
`main` を GitHub Pages のルートに、各プルリクエストをプレビュー用のサブパスに置き、プレビューURLをPRにコメントします。
ビルドは [`mise`](https://mise.jdx.dev)（`mise.toml`）経由で Deno を入れ、正しい `BASE_URL` で `deno task build` を実行します。

リポジトリ側で一度だけ設定が必要です。
**Settings → Pages → Build and deployment → Source: GitHub Actions** を選んでください。
これがないと `actions/configure-pages` が `Get Pages site failed` で止まります。
